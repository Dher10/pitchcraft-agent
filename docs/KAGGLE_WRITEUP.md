# PitchCraft: A Fact-Checked Scouting Report Generator

### Turning MLB matchups into readable scouting reports, verified line by line by a critic agent.

**Selected track:** Freestyle

**Live demo:** https://pitchcraft-agent.vercel.app
**Repository:** https://github.com/Dher10/pitchcraft-agent
**Video:** https://youtu.be/OgVPu8rFIgs

## The problem

A baseball fan checking today's schedule sees ERA, WHIP, a probable pitcher's name, and not much else that means anything without context. The real data exists: pitch mix, velocity, movement, matchup history. But it lives in dashboards built for analysts, not fans. Nobody translates "38% four-seam, 27% slider" into "this is what to watch for tonight."

PitchCraft closes that gap. It is not a prediction tool. It does not tell you who wins. It explains a starting pitcher matchup the way a knowledgeable friend would before first pitch, and it shows its work: every claim in the report is checked against the same structured data before it reaches the page.

## Solution and core concept

PitchCraft converts a day's MLB probable-pitcher matchups into fan-facing scouting reports. For an upcoming game, it explains each starter's arsenal, strengths, and risks, plus what the opposing lineup's real season splits suggest about the matchup. For a completed game, it grades each starter's actual performance and checks whether the pregame scouting notes held up.

The product decision that shapes everything else: PitchCraft is a translator, not a dashboard. The interface shows only what a fan needs to follow the game. The deeper analysis (real pitch-level data, real team splits, a deterministic grading formula) runs underneath and surfaces as plain sentences, not raw tables.

## Verify it in two minutes

1. Open https://pitchcraft-agent.vercel.app. The games carousel shows real upcoming MLB matchups with real probable pitchers, fetched from the MLB Stats API on the snapshot date shown in the footer area of each card.
2. Click any upcoming game. The starter cards show each pitcher's real season ERA, WHIP, and strikeouts. The offense sections show the opposing team's real OPS, strikeout rate, and walk rate against that pitcher's throwing hand, with a plain-language read of what it means.
3. Open "See detailed analysis." Click through the pitches: usage, velocity, and a movement card drawn from real Statcast break data. Toggle VS LHH / VS RHH and the zone chart updates.
4. Select the completed game (NYY @ BOS, marked FINAL). In the Critic Review panel, one claim carries a yellow REVISED chip: the profile claimed a put-away changeup, the critic found 12% usage and corrected it. The evidence sentence is right there.
5. Same page: both starters carry a numeric Game Score (35 and 61) with a letter grade, computed by the Postgame Grader agent.

Everything in those five steps is generated by the pipeline described below. Nothing is hand-written copy.

## Architecture: the agent pipeline

PitchCraft runs a five-agent pipeline written in Python. Each agent has a defined input, a defined output, and no dependency on an LLM call. Given the same input, every agent produces the same output every time.

1. **Data Scout** assembles the matchup packet (game info, both starters, chart data, pitch locations) and records what data is actually available, tagging the confidence level (`demo_cached` or `fetched_snapshot`).
2. **Matchup Analyst** turns that packet into structured findings: each starter's strengths and risks derived from their pitching profile, lineup pressure points derived from the opposing team's real OPS, strikeout-rate, and walk-rate splits against that pitcher's throwing hand, and three concrete things to watch.
3. **Report Writer** assembles those findings into the report the fan reads: a headline, a short summary, and sections comparing each starter against the opposing lineup, written with a fixed vocabulary that never uses betting or prediction language.
4. **Critic / Fact-check** verifies every claim the Report Writer made against the underlying data, and flags or rewrites the ones that do not hold up.
5. **Postgame Grader** runs only on completed games. It scores each starter's actual line using the original Bill James Game Score formula and produces a letter grade.

This sequence is visible on the page itself, in a "How PitchCraft Works" panel that shows each agent's status and output for the matchup being viewed. Nothing about the pipeline is hidden or simulated for the demo; it runs the same way whether it is fed cached demo data or live data fetched that morning.

Some numbers behind the current deployment: the generator runs 75+ structural validation checks on every build before writing the JSON the frontend consumes. The live snapshot powering the demo covers three real matchups, roughly 1,500 Statcast pitches per starter, per-pitch movement in inches, and real team splits for all six clubs involved. A 30-team color and identity map drives the visual system.

Choosing deterministic, rule-based agents over LLM calls was deliberate. It removes runtime cost, removes the risk of hallucinated claims slipping into a fan-facing report, and makes every output reproducible for grading. The tradeoff is that the "intelligence" lives in the rules the Matchup Analyst and Critic apply, not in a model's judgment, which is exactly why the fact-check step matters more here than it would in an LLM-based system.

## The critic loop, the differentiator

Most matchup previews are static copy. PitchCraft's report is generated, then audited, before it is shown. The Critic agent takes each factual claim in the report (primary pitch, put-away pitch, command assessment) and checks it against the pitcher's actual pitch mix and season data. If a claim does not hold, the Critic revises it and logs why.

A real example from the deployed demo: the scouting profile for one starter listed his put-away pitch as the Changeup. The Critic checked that claim against his actual pitch mix and found Changeup usage at only 12%, well below the 15% threshold for a credible put-away pitch. It flagged the claim as `revised`, corrected it to name the higher-usage pitch instead, and logged the evidence: *"Changeup usage is only 12%. Revised to reflect the higher-usage put-away pitch."*

That correction is visible on the live site's Critic Review panel, alongside every claim that was checked and supported. The panel also actively scans every report section for betting, odds, or win-prediction language and confirms when none is found, since staying out of prediction territory is a hard product constraint, not just a style choice.

## Data strategy: real, cached, and honest about both

PitchCraft runs in two data modes. `demo_cached` uses a hand-verified snapshot so the public demo always works, even with zero internet access; this is the baseline the app falls back to if any live fetch fails. `fetched_snapshot` pulls real data: today's MLB schedule and probable pitchers from the MLB Stats API, then real pitch-by-pitch Statcast data for each probable starter via pybaseball, including actual pitch mix, velocity, and per-pitch movement (horizontal and vertical break in inches). The same MLB Stats API also supplies each starter's real season ERA, WHIP, and innings, and each opposing team's actual OPS, strikeout-rate, and walk-rate splits against left- and right-handed pitching.

The deployed demo currently runs on a live snapshot: three real upcoming matchups with real probable pitchers, real arsenals, and real opposing-lineup splits, alongside one worked demo matchup that keeps the postgame grading and the critic's revision example intact and easy to verify.

I am being direct about a limitation here: there is no cron job or scheduled refresh. Live data is pulled by running one command (`python -m data_pipeline.fetchers.live_pipeline`) and regenerating the JSON. That was a deliberate scope decision, not an oversight, to avoid running paid or fragile server infrastructure for a capstone demo. In production this would run on a daily schedule; for this submission, it is a manual, documented step.

## Postgame grading with a public formula

For completed games, PitchCraft grades each starter's actual outing using the original Bill James Game Score (1988): 50 points, plus one per out recorded, plus two per inning completed after the fourth, plus one per strikeout, minus two per hit, minus four per earned run, minus two per unearned run, minus one per walk. It is the same formula behind the single-game pitcher ratings on Baseball-Reference and ESPN.

I chose a published, industry-standard formula over inventing a proprietary one on purpose. The numeric Game Score is the defensible part; PitchCraft's letter grade (A+ through F) is a readability layer on top of it, clearly labeled as such. In the worked demo matchup, a Game Score of 61 maps to a B for a starter who worked deep and limited walks, and a Game Score of 35 maps to a C- for a rough, short outing, both visible on the site with the full underlying line.

## Stack and reproducibility

Frontend: Next.js (App Router), TypeScript, Tailwind, Recharts, deployed on Vercel. Pipeline: Python standard library for the generator and all five agents, pybaseball for Statcast access. No paid services, no API keys, no login anywhere. The README in the public repository documents every command needed to run the generator, refresh live data, and build the frontend locally.

## Course concepts demonstrated

**Multi-agent system.** Five agents (Data Scout, Matchup Analyst, Report Writer, Critic, Postgame Grader) run in a defined sequence with typed inputs and outputs, visible to the user as a live pipeline trace.

**Agent skills / fact-check loop.** The Critic agent is a dedicated verification skill that checks generated claims against structured ground truth and produces auditable, revisable output. This is the project's core differentiator.

**Security.** No API keys, secrets, or credentials are committed to the repository. All MLB data sources used are public and free. The Critic also actively guards against a specific content-safety concern for this domain: it scans every report for betting, odds, or win-prediction language before publishing.

**Deployability.** The frontend is deployed on Vercel at a public URL with no login required. The full pipeline is reproducible from a public GitHub repository with documented setup steps, and the app degrades gracefully to cached data if live sources are unavailable.

## Limitations and what's next

PitchCraft is a capstone demo, not a production betting or analytics tool, and it says so on the page itself. Live data currently covers only the probable-pitcher matchups fetched in a given run, capped at three to keep fetch time reasonable; other archive rows are illustrative demo data, clearly not presented as real results. The internal "Stuff" and "Strength" signals shown in the radar chart are PitchCraft's own derived labels, not official Statcast Stuff+.

The next real step is scheduling the live fetch instead of running it manually, and extending real postgame grading to completed live games instead of only the worked demo matchup. Both are straightforward extensions of the pipeline that already exists; neither changes the architecture.
