- P0.15-D3.1: the published file now records every sentence with the catalog key and the arguments it was written from (`matchups[i].report.claims[]`, and `claims[]` at the root for the generator's sentences), and `metadata.language` says the catalog. Schema 0.3.0. The English text the fan reads is unchanged. `validate_payload` refuses a payload whose text differs from what its claims render to, or that has a sentence with no claim.

- P0.15-D1: new `docs/DATA_CONTRACT.md` and decision D34 (the contract is normative: eight rules and a registry of claims; QA verifies it). It does not change what the product does yet; the fixes follow in P0.15-D2. Rule 5 has an explicit exception (the Critic and `validate_payload` fail closed) that P1.2 reviews. `docs/data-inventory.md` is Annex A.

- P0.15-C: a Statcast answer with a malformed row is a source failure, not a smaller sample. In a pitcher frame every row must have a parseable date and a known game type; in a team-batting month also a half-inning, both teams and the pitcher's hand. The run record then shows an error (`statcast_pitcher` or `savant_team_batting`) naming how many rows and the first one, the game is not built from that answer, and a malformed month of Savant data is not cached. A frame with no rows (a debut), spring training, exhibition and all-star rows, and dates after the cutoff are still skipped without an error. Before, a game type missing in every row published a debut with 0 pitches, and one missing date among valid rows silently dropped that pitch.

- P0.15-B: every group of figures states its own scope. ERA, WHIP and innings come from the MLB API (regular season only); the strikeout, walk, home-run and batters-faced counts have the scope of the source that gave them (the API, regular season; or Statcast, which includes the postseason); the pitch data is Statcast's. The starter card shows one line ("ERA, WHIP and K: regular season through D") when they agree and two when they do not ("ERA and WHIP: regular season through D" / "K: regular season and postseason through D"). The report never says "all pitcher figures cover ..." about a starter whose groups differ: it lists what each scope covers and says they are different samples, and its rate claims say which games the counts come from ("(regular season and postseason rates)" when Statcast gave them with postseason pitches). Publication fails if a group's scope does not match its source. A starter with no figure at all (a debut) is no longer given a scope: the confidence note says "<name>: no season figures are available." A cached snapshot from before this change (one scope per summary) is rejected with the reason until the next daily run.

- P0.15-A: a live game is no longer a copy of the demo's featured game. The page shows its start time as the schedule's UTC instant, converted to the venue's time zone when the schedule gives one ("7:05 PM EDT") and as UTC otherwise ("23:05 UTC"); it never prints the demo's Los Angeles zone or the browser's. A missing venue reads "Venue not available". D33 added (live game time). The live archive row and the `generated_at` of the data file are made from the live run, not from the demo. A game whose schedule lacks a team, a team id, a probable pitcher id or a valid UTC start time is rejected with the reason and the page falls back to demo (it used to be completed with demo values). An older cached snapshot (field `start_time`) is rejected the same way until the next daily run.

- P0.14-C: the detail panel says "pitch count not available" instead of "0 pitches" when the count is unknown, and shows a dash plus "No left-handed (right-handed) batters faced." instead of 0% when the starter never faced that side; a pitch thrown less than 0.05% of the time is listed; an unknown throwing hand prints no "RHP/LHP" (it used to print RHP); the trajectory card draws no velocity meter next to "N/A". New rule in `CONTRIBUTING.md` ("Sweeps"): an item from a sweep that touches a decision boundary or a user-visible claim is fixed, not recorded. The raw `npm audit` output is kept in `docs/qa/audit-2026-10-11.json`.

- P0.14-B: the Critic decides on raw pitch counts, not on the rounded share the chart shows: a primary pitch needs 30% of the starter's pitches and a put-away pitch 15%, so 29.97% (drawn as 30.0%) now earns the warning it should. Each live row of the pitch mix carries `count` and `total` (the demo has none and keeps using the percentage), and publication fails if a live row lacks them or they disagree with the sample. A pitch thrown less than 0.05% of the time counts as thrown. The pitch-name check holds every sentence to the starter it is about, section included (a slider written in the section of the starter who never threw one is `unsupported`). A missing strength dimension no longer prints "Command signal is 0".

- P0.14-A: a game on the first day of the regular season is no longer dropped: with the cutoff before the season starts there is no Statcast range, so each starter is built like a debut (hand from the MLB people endpoint, no pitches, every pitch-based dimension limited) and the game is published. Every MLB Stats API answer the pipeline reads (schedule, season stats, team splits, series status, person, seasons) is now checked whole against an explicit schema (`data_pipeline/fetchers/mlb_schemas.py`); a missing mandatory field anywhere inside it, an error envelope or a wrong type is a recorded source failure, a valid empty list is still valid and an absent optional figure is unavailable, never zero. The season rates come from the MLB API only when it gives all four counts; otherwise valid Statcast counts are used.
