## 3. F21 (owner's two conditions)

**Incomplete.** In `_attach_sample`, when the API line gives `battersFaced` and the Statcast frame has usable `events`: `statcast_pa` = plate appearances in rows with `game_type == "R"` (same window as the API), `tolerance` = number of distinct games in the frame (`game_pk`, else `game_date`). If `statcast_pa + tolerance < api_batters_faced` the sample is incomplete (an empty frame with an API line above 0 is the extreme case: not a debut, a gap).
- **Tolerance, documented in the contract:** the API credits a batter to the pitcher who started the plate appearance, Statcast to the one who finished it, so a pitcher pulled mid-count shifts one batter per appearance. Intentional walks need no tolerance: Statcast writes an `intent_walk` row for them (17 in the real sample, all with a null `pitch_type`).
- **Calibration before relying on it (stop condition):** compare ≥ 25 real pitchers (API line vs Statcast frame), cache the pairs under `data_cache/raw` (D16: cached, non-bulk), report the observed maximum gap per appearance, and derive the offline test fixtures from those real pairs (ENGINEERING §5). If reality needs more than 1 per appearance, I stop and report.
- **Correction (as you approved):** a recorded `statcast_pitcher` error ("incomplete: N plate appearances in Statcast, M batters faced in the API line"); the starter has no pitch data (mix, velocity, movement, locations empty; `arsenal.pitches = None`, `arsenal.scope = None`: unknown, not 0); the API counts are kept. The hand still comes from the frame or the people endpoint.
- **Not covered, and said so in the contract:** Statcast with **more** plate appearances than the API (the API is the official line; not flagged), and a partial API line without `battersFaced` (nothing to compare).

**Impossible.** A check next to the manifest, `rule1:impossible_figures`, per live starter: `home_runs <= batters_faced`, `strikeouts + walks + home_runs <= batters_faced`, `batters_faced <= pitches` (codes `#home_runs_over_batters_faced`, `#outcomes_over_batters_faced`, `#batters_faced_over_pitches`). Tolerance documented: an intentional walk is a batter with no typed pitch, so `batters_faced <= pitches` can only fail falsely for a sample smaller than one pitch per batter. Added with its fix in the same commit, so no entry in the table.

**Fixtures and fakes (justification).** The matrix's fake API line says 400 batters faced to every starter whatever his frame has; the fake line becomes a function of the fake frame (batters faced, K, BB, HR counted from its events; innings from its outs), and a debut or an opening day gets the valid empty answer (the `canonical` equivalence of `tests/matrix.py` is updated). One new hard case, `statcast_gap` (API 25 batters faced, empty frame), drives the correction. Golden:
- `live_limited_arsenal` is **rebuilt**, not removed: with consistent sources, arsenal limited (< 100 pitches ≈ 26 batters faced) with strikeout and control not limited (≥ 70 and ≥ 170) cannot exist, but the F21 correction makes it real (pitch data unavailable, counts healthy from the API). So it becomes exactly that starter (`pitches = None`, `mlb_api` counts). A unit test of the writer covers the branch with a hand-built sample too.
- **The golden shows only states the pipeline produces (owner, 2026-10-15).** `live_unknown_figures` (commit b) is built by hand (`tests/golden_scenarios._unknown_figures`) because no path of the pipeline reached an unknown pitch count. When F21 makes it reachable, that scenario must be built from the real path of F21 (the pipeline fed with the `statcast_gap` sources, its starter taken from the output) or I show why it cannot; likewise `live_limited_arsenal` below.
- `live_both_limited`: both starters with coherent counts (10 pitches / 3 batters, 40 / 10).
- `live_limited_rates_only`: coherent (200 pitches / 51 batters, innings from the outs), which is reachable.

## Left on purpose, proved (adjustment 1)
