## Hard rules and verification for every commit

- Red tests first, run and seen failing for the intended reason; name the
  passing controls and record the red counts. Documentation-only commits
  add no artificial tests.
- Fix the class: sweep related producers, readers, claims and tests.
- Full verification in the default terminal, one suite at a time, in order:
  `python -m pytest`, `npm test`, `npx tsc --noEmit`, `npm run lint`,
  `npm run build`. Do not alter PATH or locale to make a command pass.
- Zero MLB/Savant requests in tests. Use existing source fixtures and fakes.
  Read GitHub's published inactivity documentation and MLB's published
  attribution notice when the relevant commits require it.
- Do not dispatch workflows or run a live pipeline. Observe CI after an
  approved push; wait for that commit's CI to be green before the next commit.
- NO commit on `v2` may touch `public/data/` or `evals/live/`. Heartbeat tests
  use temporary repositories; only the deployed bot writes the actual file.
  If a test requires changing the served file, stop and ask the owner.
- No new schema version or error code: D43's 0.9.0 covers rows 9 and 10.
- Fan-visible copy is restricted to the approved texts below. Register every
  new UI text in `docs/DATA_CONTRACT.md` section 3.3. Keep agent text in the
  language catalog (D6/D31).
- Read the relevant `node_modules/next/dist/docs/` guide before Next.js code.
- Self-review per ENGINEERING section 7 and obtain the clean-context reviewer
  verdict per `.claude/agents/reviewer.md`. Fix blocking findings; at most two
  rounds without PASS, then stop and ask. Each commit still needs the owner's yes.
- Stop on a new decision/schema/error code, a change to `DECISIONS.md` or
  `.github/workflows/`, unapproved fan-visible text, scope-changing findings,
  a non-obvious test failure, or CI red twice. Do not touch `main` or tags.
