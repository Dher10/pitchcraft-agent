Approved by the owner on 2026-10-30 (message "Resume Phase 2 under the D35 autonomy rules", with the nine guide changes). Writer guide version 0.2, digest in `evals/data/writer/guide.lock`. Authority: `docs/plans/P2.md` (P2.2/P2.3), `docs/plans/P2.4.md` section 5, D44-D51, `docs/eval-spec.md`, `docs/SECURITY.md`.

## Scope and what this does not do
- Offline only. No schema change: the candidate report is an **internal** structure (same sections as the rules report, each sentence with its evidence), never written to `public/data/` or `evals/live/`. The exact published prose schema stays an owner gate (D44/D45); nothing here admits LLM prose to publication, and rules stay live.
- Dev split only. The test split is never opened (only ids and hashes). Gemini only; no Groq call.
- Calls: only the ten B1 dev examples at the end (owner gate). Run cap 160 and experiment cap 400 Gemini HTTP calls, counted before each request is sent.

## Commits (each: red tests first, five suites one at a time, reviewer PASS, CI green)
1. **Guide 0.2 and handoff (docs).** `docs/writer-guide.md` v0.2, `evals/data/writer/guide.lock`, `tests/test_writer_guide.py`, STATUS (guide digest, disclosed deviation, backlog item, postseason finding), this plan.
2. **Glossary and writer-input projection.** `evals/data/dataset/glossary.json` + `glossary.lock`, test that file and guide table agree; `agents/writer_input.py`: closed projection of packet + findings + glossary for the writer (the same function feeds A, B1 and B2); strips `data_confidence.notes`; drops bio/recent_form/postgame/ids not needed; NFC-normalizes names; a flat evidence index (`path -> value`) with scopes.
3. **CallBudget.** `agents/call_budget.py`: durable hash-chained ledger of Gemini HTTP calls, reserve before send, run cap 160, experiment cap 400, resume, worst case 8 per item. At the cap the item finishes on rules with `call_cap_reached`, later items `not_attempted`.
4. **Writer and output checks.** `agents/llm_report_writer.py` (prompt from the guide, response schema, `run(findings, matchup_input, language)` keeping the rules writer's signature), `agents/writer_checks.py` (W1-W17 as code: evidence path and value, numbers and entities, comparisons with two values and one scope, cause words, time words, outcome words, questions, banned topics, length within 20%, sections, `validate_sentence` of P2-SEC), cascade: D49 transport policy inside, one informed content retry, then rules; path and closed codes of every attempt.
5. **Offline B1 dev runner and the ten examples.** `evals/run_b1.py` (explicit owner-PC mode, key read only by the runner, caches the exact accepted response under its request identity, resumable) and the review document of the ten outputs beside the rules text.

## Controls and negatives (tests)
Every W rule has one failing and one passing sentence; real zero vs missing; limited arsenal; Game 1 series; accent names in NFC and NFD; two cited values with different scopes rejected; comparison without both values rejected; question and non-"Watch how/whether" rejected; length 79% and 121% rejected, 80% and 120% accepted; cap reached mid-item, before the first item, resume from the ledger, 8 calls worst case; first success, technical failure then success, two failures, quota; no key means rules without a call; tests never touch the network or a key.

## Stops
Any new decision, schema or error code; fan-visible text outside the plan; a finding that changes scope; two red CI runs; two review rounds without PASS; any need to open a test-split file; the ten B1 dev examples (owner gate, show outputs beside the rules text with each path and check result).
