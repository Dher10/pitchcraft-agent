## What a packet is

For each sealed case, the matchup exactly as the live pipeline builds it from one game and the day before (`as_of`, D29):
`live_pipeline.fetch_pitcher_statcast` for both starters, `fetch_team_splits` for both lineups, `live_matchup.build_matchup`,
then `data_scout.run` (the packet) and `matchup_analyst.run` (the findings). Same code as the daily job; nothing hand-built.
Report Writer and Critic are not run: the writer is what P2 compares (A, B1, B2).

## Where each input comes from, and what it costs

| Input | Source | Requests |
|---|---|---|
| Game record (teams, ids, start time, series fields) | the cached month schedule already on disk (digest-checked) | 0 |
| Season line (ERA, WHIP, IP, K, BB, HR, BF) | the cached `gameLog` of each starter, rows dated strictly before the game | 0 MLB |
| Series standing (postseason) | the standing recorded in `selection.json` (`series.result`), built into the series object by `series.build` | 0 |
| Season dates | `selection.json` (`season`), checked against the saved calendar `data_pipeline/reference` | 0 |
| Pitch data | `fetch_pitcher_statcast`, one Statcast request per starter | pitcher_statcast, ceiling 160 (80 expected) |
| Throwing hand | only when Statcast has no usable pitches, `fetch_pitcher_hand`, cached for good | pitcher_hand, ceiling 80 |
| Lineup splits | Savant team batting; closed months are all cached; the partial month ending the day before the game | savant_open_month, ceiling 80 |

MLB: 0 new lookups (162 of 172 used). A case that would need one stops the build and goes to the owner. Gemini: 0.

## Changes to code that already exists (each with a red test)

- `fetch_pitcher_statcast(..., season_stats=None)`: when given, it replaces the `fetch_pitcher_season_stats` request. Default
  unchanged, so the daily job is untouched.
- `live_pipeline.game_record(game)`: the body of the loop of `fetch_todays_games`, extracted so the packet builder reads a cached
  schedule game through the same code (no copy of the field list). `reset_run_budgets()`: the four per-run counters, used by
  `run_live_pipeline` and by the builder at the start of each batch of five games.
- `request_ledger.mlb_source`: `people/{id}` without `/stats` is a `pitcher_hand` request (its own ceiling of 80), not an
  `mlb_people` lookup of the shared MLB ceiling. `counted_statcast_pitcher(ledger)`: reserves each Statcast pitcher HTTP request
  in the ledger before it is sent (nothing counted that source before).
- `collect_sources.HistoryStore.cached_response(pitcher_id)`: the raw `gameLog` and `yearByYear` answer from disk, digest-checked,
  never fetched; a missing file raises `HistoryMissing`.

## New module `evals/build_packets.py`

- `season_line_as_of(response, official_date)`: sums the regular-season game-log rows dated strictly before the game date
  (innings as outs, earned runs, hits, walks, strikeouts, home runs, batters faced); ERA and WHIP from those sums, formatted as
  the API does. No row before the date: `{}` (unavailable, as `fetch_pitcher_season_stats` returns on no splits). A row without a
  needed field: `{}` for the whole line (unknown is never zero). A row dated on or after the game date is never summed (leakage
  test uses a row on the game date). Cross-check: the sum of the whole season equals the API's own `yearByYear` season line.
- `build_case`: validates `as_of = game date - 1` (`bd.check_as_of`), the game's status is set to what the schedule said the day
  before (Preview/Scheduled), because a final status and its score are not known as of that day; builds the live game, runs
  `generate_demo_json._game_unsafe` and records its verdict; builds the matchup, the scout packet and the analyst findings.
  stdout of the live pipeline is discarded (it prints pitcher names and counts); a test asserts nothing is printed.
- `freeze`: writes `packets/{dev,test}/<case_id>.json` and `findings/{dev,test}/<case_id>.json` (canonical JSON), and
  `packets_manifest.json` with each file's SHA-256, the SHA-256 of the cached inputs it read (schedule files, history files), the
  requests it used per source, and the SHA-256 of the manifest body. It refuses to rewrite a frozen set.
- The CLI prints only case ids, counts and hashes, never packet content. Test-split content is never printed, read back or
  summarized by this task; the committed-data tests read hashes only.

## Tests (red first, each seen failing)

1. Season line: strict `<` date (a row on the game date and one after change nothing); sums and formats; empty and
   partial-field cases are `{}`; non-regular-season rows excluded; the full-season sum equals the `yearByYear` line.
2. `fetch_pitcher_statcast(season_stats=...)` makes no season-stats request; default path unchanged.
3. Ledger: hand vs people routing; `counted_statcast_pitcher` reserves before sending, refuses over the ceiling, marks failures.
4. Builder over recorded fixtures: no network (any `_get_json`/Savant call fails the test); series from the record (Game 1 has no
   result; a later game's standing excludes it; a series-ending game carries no final result); status is upcoming; `as_of` other
   than the day before is refused; nothing printed; byte-identical output on a rerun.
5. Freeze/manifest: packet set equals the sealed case ids exactly (missing, extra and swapped-side files fail); hashes match
   file bytes; a frozen set is not rewritten; the manifest hash pins the body.
6. Committed set (after the build): the same checks on `evals/data/dataset`, reading hashes only.

## Execution and stops

1. Offline preflight prints, per source, the requests the build would need given the caches. If any exceeds a ceiling, or any
   MLB lookup is needed, stop and ask.
2. The build runs in batches of five games, one pipeline "run" each (budgets reset per batch), paced at 2 s, resumable.
3. Stop for the owner: a case that cannot be built (a failed starter would drop the game in the daily job, but the 40 ids are sealed).
4. Then the writer guide draft (`docs/writer-guide.md`) from dev packets only, and stop for approval.
