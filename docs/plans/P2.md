### Required writer guide before P2.2

After P2.4 supplies real dev packets, draft `docs/writer-guide.md` and stop
for the owner's approval before building the writer or its prompt. This is
a prerequisite within P2.2's scope, not permission to write the guide from
invented packets during the present credentials stop. The guide must cover:

- Audience: a casual fan, including someone who does not know pitching jargon.
- Allowed facts: only facts in the input packet. The model's outside knowledge
  is not evidence, even when a statement is true.
- Forbidden content: predictions, betting, outcomes, injuries, history,
  awards and any other fact absent from the packet. No deception or
  effectiveness inferred from movement alone. The named forbidden topics
  remain forbidden even if the model knows them or finds them in the packet.
- Style: explain jargon on first use, write short sentences, give concrete
  things to watch and treat each starter symmetrically, while respecting
  the evidence and limited flags available for each.
- Three to five good/bad example pairs built from real dev packets, each
  with its case ID, evidence paths and the reason the bad version fails.
  Use dev only; never borrow test examples.

Give guide rules stable IDs for S1, including jargon-on-first-use and each
forbidden phrasing rule. Version the writer prompt with the approved guide
and retain both digests in run manifests. A changed guide/prompt is a new
version, never a silent edit. The later ten B1 dev reports are a separate
owner checkpoint from these guide examples and the ten A reports for F1.

R1 adds relevance and packet-only knowledge: every sentence concerns this
game, these starters or these lineups, and states no absent fact. Its code
check flags entities/numbers absent from the packet; its judge checks the
meaning. True-but-unsupported fails R1. S1 judges each guide rule as binary
pass/fail. Calibrate both on dev human labels with an 85% agreement target
per dimension; preserve S1 per-rule results so an aggregate cannot hide a
broken rule. R1 requires 100% on held-out test; S1 informs the one B2 change
and adds no separate style pass-rate ship threshold.
