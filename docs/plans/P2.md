## Writer guide prerequisite

After P2.4 supplies real dev packets, draft `docs/writer-guide.md` and obtain
owner approval before P2.2's writer or prompt. Version guide/prompt together,
with stable S1 rule IDs, applicability, digests and examples:

- Casual-fan audience; only facts in the input packet, even if outside facts
  are true. No predictions, betting, outcomes, injuries, personal life,
  history, awards or other facts absent from the packet. Named forbidden
  topics remain forbidden even if present.
- No deception or effectiveness inferred from movement alone. Use the
  existing no-spin reference and approved sideways wording; no unverified
  arm/glove-side convention. Comparisons need comparable measurements for
  both pitches; measured zero stays measured, missing stays unavailable,
  and limited arsenal/unmapped families suppress descriptions.
- Python computes everything; the writer never calculates. Intensity words
  only from existing D24/D25 labels and their sample thresholds. Do not
  invent percentiles, league comparisons or stronger adjectives.
- No causal words such as "because" or "due to" unless the cause is explicit
  in packet evidence. Neutral, factual language about real people.
- Explain jargon on first use, using approved definitions in the shared
  packet; short sentences, concrete things to watch, symmetric treatment of
  both starters, both available offense reads and every limitation.
- Three to five good/bad pairs from real dev packets, each with case ID,
  evidence paths and failure reasons. Never invent examples or use test.

F5/F7 improvements must appear in existing visible report fields; new
visibility/copy requires approval. Do not hide limitations to shorten prose.

## Groq call/token ledger and calendar consequence

The Oct 24 research counted separate dimensions; the owner now approves
bundling. Exact CALL arithmetic below; token CAPS are assumptions, not
measurements. Report call: 4,000 input + 1,500 generated including reasoning
= 5,500. Ordered U1: 5,500 + 500 = 6,000. Invalid/truncated responses are
missing, never passes; do not truncate evidence to fit. P2.1 establishes
measurement; replace caps/output budgets/packing with complete-request
measurements once real packets and first B1 reports exist, before the full run.

60 B-vs-A pairs x both orders = 120 U1 calls. Three total dev calibration
passes (including final) add 3 x (40 reports + 40 ordered U1) = 240 calls.
This is a capacity allowance, not a requirement to waste three passes if
calibration succeeds earlier. Exact final-dev reuse subtracts 40 + 40 = 80.
