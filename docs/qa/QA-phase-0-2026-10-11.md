### QA2-01 — equal cutoff strings are not a safe cached-input boundary

**Expected:** the generator accepts live cached input only when the record proves ownership and its dates are consistent with the game and D29. A cutoff on or after the game must not reach a public packet (P0.12-A, PRD FR1, as-of scenario).

**Actual:** `_snapshot_mismatch` checks equality of `target_date`/`fetched_date` and `as_of` strings, then returns `None`. It never parses the dates or enforces `as_of < game_date`, and publication validation adds no such check. A matching pair with game date `2026-07-15` and cutoff `2026-07-20` reaches `build_payload` as `fetched_snapshot`. The fixture's July 20 pitches are then published with their late scope and validation passes.

**Evidence:** the real resolver, real fetcher/processing, all agents and `validate_payload` produced:

```text
UNSAFE_RESOLVER_PUBLICATION fetched_snapshot 2026-07-15
{'pitches': 150, 'scope': {'kind': 'regular_season', 'through': '2026-07-20',
 'label': 'regular season through 2026-07-20'}} validation= True
```

Reproduce with `python -` from the repository; all source responses are synthetic and publication stays in memory:

```python

from tests.test_live_starters_no_demo_fields import _fake_live_game
from tests.test_stale_snapshot import good_run

with patch.object(p, 'season_dates', return_value=(date(2026,3,25), date(2026,9,27))), \
     patch.object(p.urllib.request, 'urlopen', return_value=FakeResponse(API_STATS)), \
     patch.object(p, 'statcast_pitcher', return_value=frame(game_date='2026-07-20')):
    late = p.fetch_pitcher_statcast(11, 'Late Data', as_of='2026-07-20')

    combined_charts={'pitch_mix': p._combine_pitch_mix(late, late),
                     'velocity_by_pitch': p._combine_velocity(late, late)})
game['home_starter']['name'] = 'Other Late Data'

            'as_of': '2026-07-20', 'live_games': [game]}

                  run if name == 'live_run' else snapshot):
    live, status = g._resolve_live_input()

    payload = g.build_payload()

The old missing-ID probe is fixed. Equality alone does not establish the additional date-consistency guarantee, and the reproduced path reaches the public-payload validator, so this is a Blocker under the protocol's leakage rule.

**Smallest suggested fix:** parse and validate run/snapshot dates and each game's effective cutoff against its official date before accepting the cache; reject invalid relationships explicitly. Add a publication-boundary test for a matching but unsafe pair.
