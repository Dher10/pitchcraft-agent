### QA6-01 — finite is checked, plausible is not

**Expected.** D34 rules 1 and 2 and `docs/ENGINEERING.md` section 1: a malformed numeric cell is a recorded source failure that disables the affected figure and nothing else. QA5-03 asked that unusable measurements cannot reach the public file as numbers and that infinite locations do not turn into plausible coordinates. `DATA_CONTRACT.md` rule 2 ("Finite measurements") defines the fix as finiteness only, so the contract is met as written; the class "numeric cell the source got wrong" is not closed.

**Actual.** `_finite_pitch_measurements` (`live_pipeline.py:874`) tests `np.isfinite`. Nothing tests a range. The API schema accepts any `int` (`mlb_schemas.py:279-282`), and the velocity check only requires `> 0` (`provenance.py:383-386`).

Probe E2 (API line through `fetch_pitcher_statcast → build_payload → validate_payload`, mocked transport):

```text
negative strikeouts (-5)       -> validated fail=0 | era= 3.10 k= -5 | errs= []
negative battersFaced (-19)    -> STOPPED (whole file)   [only by a derived check]
era placeholder '-.--'          -> STOPPED (whole file)
```

Probe B2 (Statcast column replaced by one finite value, same path):

```text
pfx_x -50.0       fail=0  h_break=-600.0                 errs=[]
pfx_x 9999.0      fail=0  h_break=119988.0               errs=[]
pfx_x 1e6         fail=0  h_break=12000000.0             errs=[]
release_speed 9999.0 / 1e6  fail=0  velocity=9999.0 / 1000000.0 errs=[]
plate_x -50 / 9999 / 1e6    fail=0  x=0.0 / 1.0 / 1.0 (clipped to the chart edge) errs=[]
```

And one finite value that overflows the mean (probe B, `1e308` in `pfx_x`, `pfx_z` or `release_speed`): numpy warns `overflow encountered in reduce`, the published number is `inf`, and `validate_payload` raises `ValidationError("every payload number is finite")`. The generator stops and keeps the previous file. That is the documented fail-closed exception, but it means one bad cell of one pitcher stops every game, which is the opposite of rule 5.

**Reach.** Needs a source that sends impossible values. The repository's own method (QA runs 1 to 5) treats that as in scope.

**Reproduce.** Probe files are not in the repository; they are small variants of QA5's probe B (`tests/test_live_sample_pipeline.py` helpers `events_frame`, `API_STATS`, `FakeResponse`, and `tests/live_helpers.py`): set a column of `events_frame()` to the value above and call `fetch_pitcher_statcast` for both starters, `build_payload`, `validate_payload`; for the API case, set `stats[0].splits[0].stat.strikeOuts = -5`.

**Violates.** Intent of D34 rules 1 and 2; `docs/ENGINEERING.md` section 1; the class of QA5-03.

**Smallest fix.** At the same boundary: per-column physical bounds (for example `0 < release_speed <= 130`, `abs(pfx) <= 6`, plate coordinates within a few feet of the zone) recorded as `malformed_rows` for the group, a non-negative minimum in `mlb_schemas` for counts, and an `inf`-safe aggregation. Add one test per column.

### QA6-02 — the git guard is narrower than D35 says

**Expected.** AGENTS.md: "Git safety is a hook, not a promise", blocking pushes to anything but `v2`, any operation on `main` or a tag, force flags, `rebase`, `reset --hard`, `--no-verify`. D35: "Git safety rules are enforced by a hook". QA area 5: the hook cannot be bypassed by the documented workflow.

**Actual.**
1. `.claude/settings.json` has `"matcher": "Bash"` only. The PowerShell tool, which is the primary shell in this environment, is not hooked. Evidence: `git config --get core.hooksPath` through the Bash tool is blocked (`Blocked by .claude/hooks/git_guard.py: core.hooksPath is not changed (D35)`); the same command through the PowerShell tool ran and printed `.githooks`.
2. Inside Bash the guard reads only commands that start with `git`. `decide()` run on these commands returned "allow":

```text
bash -c "git push --force origin main"     sh -c 'git push origin main'
eval "git push origin main"                powershell -Command "git push origin main"
cmd /c git push origin main                x=git; $x push origin main
python -c "import subprocess; subprocess.run(['git','push','origin','main'])"
git filter-branch --all                    git branch -D v2        git remote add evil https://x.y/z.git
```

   The module docstring says an unreadable command is not blocked, and AGENTS.md says "PreToolUse on Bash", so the scope is documented; the claim "a hook, not a promise" is stronger than what the hook covers.
3. `gh api repos/Dher10/pitchcraft-agent/branches/main` returns `"protected": false`. The only barrier to a force push to `main` or a moved tag is therefore this client hook plus the permission prompts of the tool. (The rulesets endpoint timed out; I could not check tag rulesets.)
4. `git_guard.py:297-298` blocks `git config core.hooksPath` even as a read (`--get`, or bare), while `docs/CONTRIBUTING.md:87` tells every agent to run exactly that to check the hook is active. The check required by the docs cannot run in a Claude Bash session.

**Why Medium and not High.** The control protects against an agent breaking written rules, no data or secret is exposed, the scope is written down in AGENTS.md, history and `main` are intact today (`git rev-list --count v1.0.0-kaggle..main` is 0, tag unchanged), and the remedy is cheap. If the owner reads D35 as "no force push can happen from any tool", this is a High; I leave that call to the owner and list it as a condition.

**Reproduce.** Run the two `git config --get` commands above through each tool; run the `decide(command, git)` function of `.claude/hooks/git_guard.py` from a Python shell with a fake `git` runner on the list above.

**Smallest fix.** Add a `PowerShell` matcher with the same script, make the parser look inside `bash -c`, `sh -c`, `eval`, `powershell -Command` and `cmd /c` strings (or block those wrappers when the string contains `git`), allow reads of `core.hooksPath`, and add a GitHub ruleset that blocks force-push and deletion on `main` and `v1.0.0-kaggle` while allowing the Actions bot path of D15.
