### 1. Spec conformance

### 2. Data integrity and leakage
- `data_pipeline/archive.py` (`carry_forward`):
  - Strictly rejects `demo_cached` and `demo_fallback` files from supplying any archive rows (`test_demo_origins_never_supply_archive_rows`).
  - Requires all carried-forward matchups to have `level == "fetched_snapshot"` and `postgame is None`.
  - Enforces `row["date"] < target` so today's report never enters past reports.
  - Dedupes by `{date}:{matchup_id}` and caps at 60 rows, newest first.
  - Grade and result labels are strictly `None` (no automated postgame invented).
  - Malformed previous files raise `ArchiveError` and fail closed (leaving candidate untouched and daily exiting 1).
- No demo data leaks into live mode on game days or no-games days.

### 3. Logic correctness
- **F8 (pitch order per side):** `DetailedAnalysis.tsx` sorts starter pitches by published selected-side usage descending, then overall raw count descending, then pitch name. Side toggle switches to first pitch of that order. Pitches with raw overall count 0 are hidden; pitches thrown overall but with rounded 0.0% side usage are retained at the end.
- **F10:** Strength Profile is hidden in live mode (`!live`).
- **F12:** Both starters' strength lines render in the matchup summary header (`matchup.report.short_summary.slice(0, 2).map(...)`).
- **Heartbeat 30-day rule:** `scripts/publish_data.py` (`heartbeat_due`) checks if time since last bot commit is strictly greater than 30 days (`now - previous > timedelta(days=30)`). Exactly 30 days is a control and does not trigger heartbeat. Human commits in between are ignored and cannot reset the bot's clock.
- **Scope labels (F3):** Regular season cutoff on or after calendar end date produces `{year} regular season`. Cutoff before end date produces `{year} regular season through {month} {day}`. Postseason produces `{year} regular season and postseason through {month} {day}`. English month abbreviations are explicit, avoiding OS locale drift.

### 4. Error handling
- No games scheduled is a valid live state: `live_pipeline` produces `status: "no_games"`, `daily.py` writes atomic candidate and exits 3, `daily.yml` treats exit 3 as success.
- Source failures, malformed records or invalid snapshots exit 1 and leave candidate file untouched.
- `publish_data.py` rolls back both the target data file and the heartbeat file upon any failure in allowlist check, git add or commit.
