### QA3-01 — Preview deployment gated by Vercel Authentication

- **What is wrong:** The preview release candidate URL `https://pitchcraft-agent-kadd1ouih-edherdenez-6959s-projects.vercel.app` is protected by Vercel Deployment Protection (Standard Protection / Vercel Authentication). Any unauthenticated HTTP request (curl, fetch, Playwright) is intercepted at the Vercel edge and redirected via HTTP 302 to `https://vercel.com/sso-api?url=...` and then HTTP 307 to `https://vercel.com/login`, rendering "Login – Vercel". As a result, the release candidate cannot be inspected or tested by external QA on the remote preview URL without logging into the owner's Vercel team account.
- **Evidence:**
  ```
  === GET https://pitchcraft-agent-kadd1ouih-edherdenez-6959s-projects.vercel.app/ ===
  Status: 302 Found
  Location: https://vercel.com/sso-api?url=https%3A%2F%2Fpitchcraft-agent-kadd1ouih-edherdenez-6959s-projects.vercel.app%2F&nonce=...
  Final URL in Playwright: https://vercel.com/login?next=%2Fsso-api%3Furl...
  Page Title: Login – Vercel
  ```
  Screenshot captured: `scratch/screenshots/preview-redirect-landing.png`.
- **Expected vs Actual:** Expected the preview URL to serve the public release candidate frontend. Actually, Vercel Deployment Protection intercepts all requests with a 302 redirect to login.
- **How to reproduce:** Run `curl -I https://pitchcraft-agent-kadd1ouih-edherdenez-6959s-projects.vercel.app/` or navigate to it in a browser without an active Vercel session.
- **Decision or scenario:** Previews are intended to allow release candidate verification prior to production merge.
- **Suggested fix:** In the Vercel Dashboard under **Project Settings > Deployment Protection**, temporarily disable "Standard Protection" for Preview Deployments, or generate a shareable preview link with a bypass token (`_vercel_share=...`), or verify the preview within an authenticated owner session before merging PR #3.

### QA3-02 — Turbopack postcss panic on Windows AMD64

- **What is wrong:** Running the default `next build` command (which defaults to Turbopack in Next.js 16) panics on Windows AMD64 during PostCSS evaluation of `app/globals.css`. Turbopack emits:
  `Error [TurbopackInternalError]: [project]/app/globals.css [app-client] (css) Caused by: creating new process - node process exited before we could connect to it with exit code: 0`.
  The build exits with code 1 and writes a panic backtrace to `AppData\Local\Temp\next-panic-*.log`. Running `npx next build --webpack` compiles successfully in 3.4s without errors.
- **Evidence:**
  `next-panic-a326f36836b8500f2dce81eadecc2379.log`:
  `Execution of evaluate_webpack_loader failed -> creating new process -> node process exited before we could connect to it with exit code: 0`.
- **Expected vs Actual:** Expected `next build` to complete cleanly with Turbopack on all supported platforms. Actually, Turbopack's Windows child process IPC fails during webpack loader evaluation.
- **How to reproduce:** Run `npm run build` on Windows in PowerShell.
- **Decision or scenario:** Does not impact Vercel production or CI builds, which run on Linux AMD64 containers where Turbopack succeeds.
- **Suggested fix:** For local Windows production builds, execute `npx next build --webpack`, or add `"build:webpack": "next build --webpack"` to `package.json`.

### QA3-03 — Production (release 2) lacks Content-Security-Policy headers

- **What is wrong:** The live production deployment (`https://pitchcraft-agent.vercel.app/`) currently serves release 2 (`51b24ef`). Response headers on `/` and `/quality` omit `Content-Security-Policy` and `X-Frame-Options`.
- **Evidence:**
  Production response headers on `GET https://pitchcraft-agent.vercel.app/`:
  `cache-control: private, no-cache, no-store, max-age=0, must-revalidate`
  `strict-transport-security: max-age=63072000; includeSubDomains; preload`
  `x-matched-path: /`
  `x-powered-by: Next.js`
  `x-vercel-cache: MISS`
  (`content-security-policy` is absent).
- **Expected vs Actual:** Production release 2 did not yet have the P2-SEC security boundaries.
- **Decision or scenario:** Addressed by P2-SEC (commit `0f0567d`) included in Release 3, which adds `proxy.ts` and `next.config.ts` headers.
- **Suggested fix:** Merging PR #3 into `main` will deploy Release 3 and activate full nonce-based CSP on production.
