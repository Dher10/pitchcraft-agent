### 2026-10-13 — P0.15-D3.1 phrases and claims (Claude Code, gated)

- **Mechanism (a simplification of the approved design):** the plan said a context (`contextvars`) would collect the phrases while the agents run. Collecting turned out to be unnecessary: `Catalog.__call__` returns a `Phrase`, a `str` that carries its catalog key, its arguments and the starter it is about, so the record travels with the text and `attach_claims` finds it by walking the text fields of the payload. A phrase that never reaches the file is never recorded. The only context left is `Catalog.subject(slot)`, set by the agents where a sentence is about one starter. Phrases given as arguments stay phrases; `Catalog.join` and `Phrase.capitalize` build sentences out of sentences (pseudo keys `@join`, `@capitalize`); any other string operation gives a plain `str`, and a plain `str` in a text field is refused.
- **Where the sentences were plain strings (call sites changed, text unchanged):** the analyst joined phrases with f-strings and `" ".join` / `"; ".join` (`away_vs_home`, `_live_pitcher_read`, `_offense_read`, `_scope_notes`, `_join`), the writer in `_arsenal_scout` and `_confidence_note`, the critic in the unsupported-names and betting-terms evidence, and the generator wrote the workflow, the data label and the live confidence note as f-strings (now keyed templates in `data_pipeline/generator_texts.py`, text identical). The 14-scenario English golden file and the served demo text are unchanged (the regenerated `public/data/pitchcraft-demo.json` differs only by the version, `metadata.language` and the claims).
- **Files:** new `data_pipeline/claims.py`, `data_pipeline/generator_texts.py`; changed `agents/language.py`, the four text agents, `data_pipeline/{schema,validators,generate_demo_json,live_matchup,demo_inputs}.py`, `lib/types.ts` (optional `Claim`, `claims`, `language`), `DATA_CONTRACT.md` (claim record, pseudo keys), `PLAN.md` (D3 split into D3.1 to D3.3, the tolerance goes with the last fix of D2.5).
